## 核心组件

### 1. ServiceTaskManager
负责管理服务任务会话的生命周期：
- 创建服务管理任务会话
- 同步状态到主会话
- 处理用户交互（停止、重试、查看日志）

### 2. ServiceManagementSkill
AI Skill，定义服务管理的执行逻辑：
- 解析服务配置
- 执行启动/停止/重启操作
- 健康检查
- 错误处理

### 3. ServiceTaskSessionView
自定义任务会话视图：
- 显示服务启动进度
- 实时日志输出
- 操作按钮（停止、重试）

## 工作流程

### 启动服务流程

```
1. 用户点击「启动」按钮
   │
2. ServiceRow 调用 ServiceTaskManager.startService(service)
   │
3. 创建任务会话
   ├─ 生成系统消息到主会话: "已拆出任务处理"
   ├─ 创建 AgentTaskSession
   └─ 添加到 taskSessions
   │
4. 启动 AI 执行 (CommandRunner.executeServiceTask)
   ├─ 构建服务管理提示词
   ├─ 调用 AI (带工具调用能力)
   └─ 实时更新任务会话消息
   │
5. AI 执行过程 (流式更新到任务会话)
   ├─ [检查环境]
   ├─ [执行启动命令]
   ├─ [健康检查]
   └─ [返回结果]
   │
6. 任务完成
   ├─ 更新任务状态: completed / failed
   ├─ 更新主会话系统消息
   └─ 更新 ServiceManager 中的服务状态
```

### 异常处理流程

```
任务失败
   │
├─ 任务会话显示错误信息和[重试]按钮
├─ 主会话显示: "任务遇到问题，点击查看详情"
└─ 用户可以在主会话询问: "为什么服务启动失败"
    └─ AI 可以看到任务历史，帮助诊断问题
```

## 关键设计决策

### 1. 为什么用任务会话而不是直接发送消息？

- **异步执行**: 服务启动可能需要几十秒，不阻塞主会话
- **进度可见**: 用户可以在任务标签页看到实时进度
- **可管理**: 可以停止、重试、查看历史
- **异常处理**: 失败后用户可以在主会话继续询问

### 2. 任务会话如何与主会话关联？

```swift
// 1. 创建时发送系统消息到主会话
let message = ChatMessage(
    role: .system,
    content: "服务「小红书 MCP」启动任务已创建",
    linkedTaskSessionID: session.id  // 关联任务
)

// 2. 任务更新时同步更新主会话消息
updateLinkedMainMessage(sessionID: session.id, content: "服务启动成功")

// 3. 用户点击主会话消息可跳转到任务详情
```

### 3. AI 如何执行服务管理？

通过 Skill 系统：

```swift
enum AISkill: String, CaseIterable {
    case serviceManagement = "service-management"
    // ... 其他 skills
}

// Skill 执行时可以使用工具：
// - shell: 执行启动命令
// - read_file: 查看日志
// - service_status: 检查服务状态
```

## 实现步骤

### 阶段2: 任务执行

1. 自定义服务任务会话视图
2. 添加实时进度显示
3. 添加操作按钮（停止、重试）

### 阶段4: 异常处理
1. 错误信息同步到主会话
2. 重试机制
3. 日志查看功能

## 用户交互流程示例

### 场景1: 正常启动

```
[用户] 点击「启动小红书 MCP」
[系统] 创建任务会话，显示在主会话: "已拆出任务处理"
[AI]   在任务标签页执行:
       "检查工作目录... ✓"
       "检查端口占用... ✓"
       "执行启动命令..."
       "捕获PID: 12345"
       "健康检查通过 ✓"
[系统] 任务完成，主会话更新: "服务启动成功"
```

### 场景2: 启动失败

```
[用户] 点击「启动小红书 MCP」
[AI]   执行任务...
       "检查工作目录... ✓"
       "执行启动命令..."
       "健康检查失败 ✗ Connection refused"
       "查看日志... 发现端口被占用"
[系统] 任务失败，主会话显示: "启动遇到问题"
[用户] 在主会话问: "为什么启动失败"
[AI]   "根据任务日志，端口 18060 被进程 5678 占用..."
[用户] "帮我停止那个进程"
[AI]   执行停止进程...
[用户] 点击「重试」
[AI]   重新执行启动任务...
```

这个方案既保留了任务会话的异步优势，又确保了用户感知和异常处理能力。
